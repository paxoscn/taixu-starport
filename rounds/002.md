在../taixu-demo使用该库时发现了 1 个库缺陷 + 若干 API/生产化缺口。

G1（中低）可重复任务冷却结束后,TaskView 仍展示上一轮进度

复现路径:

接取 daily 任务 → 完成 → 领奖 → 冷却结束
task_view.status = Available
但 objectives[].progress 仍是上一轮的 1/1
accepted_at_ms / completed_at_ms / claimed_at_ms 仍是上一轮的值

如果冷却结束但当前因区域/等级/前置不满足而不可接取,状态会显示 Claimed 而不是 Locked,客户端无法区分“冷却中”和“已冷却但条件不满足”。

- 探针:tests/second_round_probe.rs(默认 #[ignore],避免污染第一轮验收)
- 命令:cargo test --test second_round_probe -- --ignored → 当前按预期失败
- 位置:src/game.rs 的 task_view_in_state / task_status_in_state
- demo 规避:web/app.js::taskCard 对 status=available && claimed_at_ms!=null 的任务把 metric 进度归零、隐藏旧时间戳

这是缺陷,不是纯设计偏好。建议库侧修复:新周期视图使用空计数器/空时间戳,并区分 Locked。
